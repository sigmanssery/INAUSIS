# 1. 這個專案在做什麼

生物擬態觸覺前端,跑在 Tang Nano 9K(GW1NR-9C,27 MHz)上。

**核心主張(TTCGS):** 在感測層就把時間結構編碼成三個尺度的 Difference-of-Gaussians
(對齊 RA-I / SA-I 機械受器頻帶),輸出 18 維特徵向量加一個 18 位元的注意力遮罩,
**把「資料到決策」的映射留給下游**。論文的立場叫 **encode and defer**。

    raw -> DoG 三尺度 -> z-score flag -> 18-bit mask -> 51-byte frame + CRC
                                                     -> Manchester 單線 -> SoC
                                     <- 反向通道改寫門檻(閉環)

目標:preprint(TechRxiv/arXiv)→ IEEE Sensors Journal,兩段式。

# 2. 會浪費你好幾天的十個坑

> 這一節不是理論,是**每一條都真的踩過**。

### 2.1 `MIRROR=0` 完全沒有 UART 輸出

`ttcgs_board.v` 的 `MIRROR=0` 分支是 `assign uart_tx = 1'b1;` —— **綁死高電位**。
論文報資源的那個組態**從主機端量不到任何東西**,幀只走 Manchester 單線鏈路。

燒了 MIRROR=0 之後 `log_frames.py` 讀到 **0 幀**,那**不是故障**。

| 組態 | 用途 | 可量測 |
|---|---|---|
| MIRROR=0 | 論文報資源 | **否** |
| MIRROR=1 | **所有實測** | 是 |

**所有實測資料(soak、語料庫、下限)都是 MIRROR=1 錄的。**

### 2.2 `Verify Failed at 0` 是假警報

每次燒 flash 都會出現。**真憑據是 User Code 有沒有隨 bitstream 改變**
(v6 `0x468B` / v10 real `0x601A` 等)。不要為此重燒或懷疑 flash 壞了。

### 2.3 絕不要對這塊板跑 Zadig

libwdi 驅動會跟 FTDI 打架,把裝置弄成 `CM_PROB_FAILED_START`(code 10),
要手動清 `oem*.inf` 才救得回來。**拔插後介面 B 出問題就換一個 USB 埠。**

### 2.4 燒錄一律用 `flash.ps1`

`programmer_cli` 少了 `--location` 會**永久卡死**(Ctrl+C 也不理),
殘留行程會鎖住 USB。`flash.ps1` 會自動探測 JTAG 通道。

    .\flash.ps1 -Check                    # 只讀 device code
    .\flash.ps1 -Fs xxx.fs                # 燒 SRAM(斷電即失)
    .\flash.ps1 -Fs xxx.fs -Flash         # 燒內建 flash(過夜量測用這個)

### 2.5 Gowin 所有 target 共用一個 `impl/`

換一個 top 去合成就會**無聲地覆蓋**。**跑完立刻歸檔**,而且
**判定成功要看錯誤數,不要看 `project.fs` 存不存在**(曾經建置失敗但腳本
照印成功訊息加一份陳舊報告的數字)。

### 2.6 `check_stream.py` 不能讀量產韌體

它是給 `dual_*` 那組**文字**輸出的 bitstream 用的。量產 `ttcgs_board` 送
**51 位元組二進位幀**,要用 `log_frames.py`。拿 check_stream 去讀會看到
「非可列印 92%」—— 那是正常的。

### 2.7 改完 RTL 一定要重跑建置(這錯犯了三次)

資源數字錯過三次,每次都是因為改了 RTL 卻引用舊報告。
**引用資源前也要確認 `DEBUG_TAPS=0`**(`dsp_chain.v`)。

### 2.8 Verilog 有號性(踩過兩次,其中一次讀了四次程式碼沒找到)

- **串接永遠是無號的** —— `{a,b}` 不管 a、b 有號無號,所以 `>>>` 會變邏輯右移
- **`~x + 1'b1` 會把整個三元式降為無號** —— 負數被當無號平方

除錯方法:**把中間量接到空的 dim 上比對**(dims 14~17,`DEBUG_TAPS=1`),
不要靠讀程式碼。

### 2.9 定點移位:先看被移位的數有多大

    thr <- thr + ((target - thr) >>> 12)      // 災難

門檻只有 ~118,`>>>12` 讓**正差變 0、負差變 −1**(算術右移向 −∞),
門檻 **0.17 秒歸零**,88~99% 的幀觸發。修法是累加器加寬當小數。

同類錯誤:**把編譯期常數寫成 `*`**。`parameter N_SQ = 25` 寫成
`N_SQ * cal_var16` 讓工具推導出一顆真乘法器,**白丟 2.5 個 DSP macro**。
改成依設位元展開的移位加法樹後 DSP 從 75% 回到 50%。

### 2.10 heredoc 會弄壞 Verilog patch

bash heredoc 在這個環境下反覆失敗。**要改多行 RTL 就把 Python patch 寫成檔案再執行**,
不要用 `python - << EOF`。

# 4. 今晚(08-29/30)做完的事,以及為什麼那樣做

## 4.1 自適應雜訊估計 v6 → v10

**根因(可計算):** `CAL_N=512` 對 d2(G_σ3,自相關時間 **τ=84 幀**)
只有 **~6 個獨立樣本**。χ² 六自由度 → σ 估計 0.52×~1.45× →
**標稱 5σ 實際落在 2.6σ~7.3σ**。實測六次開機 0.007%~0.083%,與模型吻合。

**分佈是高斯的**(kurtosis 2.9)—— **錯的是估計器不是模型。**

演進(每一版都是被前一版的實測失敗逼出來的):

| 版本 | 做法 | 壞在哪 |
|---|---|---|
| v6 | 一次性校正 + 5σ | 跨開機 0~0.083% |
| v7 | 每樣本 EWMA(第一版) | **定點移位捨入,0.17 秒歸零** |
| v8 | 每樣本 EWMA(修好) | **次閾值訊號自我遮蔽,下限 100%→67%**,DSP →70% |
| v9 | **整窗接受/拒收** | 1/5 輪開機有 80 ms 暫態 |
| **v10** | **+ 2σ² 保守種子 + `uncal` 撐到收斂** | **目前無已知問題** |

**v8 為什麼賠掉下限(通則):** 守衛區只在**觸發**時武裝,所以**次閾值刺激沒有守衛** ——
能量進入雜訊估計、推高門檻、把自己推得更低於門檻。正回饋。
靜止測試(沒訊號)和按壓測試(訊號大到必觸發)**都看不到**。
雷達裡叫 **target masking**。

**v9 的關鍵是「能不能拒絕」:** 連續平均無法拒絕,**整窗取捨可以**。
而且**拒收判準必須相對** —— 55 counts 的按壓只貢獻 700~1400 counts²,
遠低於 `VAR_CEIL=20000`,卻是靜止 4.7 的 **300 倍**。

**v10 的兩處:** 種子取 **2σ²**(種子誤差對稱但後果不對稱:偏低誤觸發、
偏高只是短暫遲鈍),`uncal` 撐到累積 8 個接受窗。

`uncal` 的**語意已改**:從「一次性校正做完了」變成「**估計已收斂到可信**」。
論文 §III-E 要跟著改。

細節:`DATA/ADAPTIVE_BASELINE_2026-08-30.md`

## 4.2 常數乘法強度削減

`parameter N_SQ` 寫成 `*` → 工具推導出 40×5 真乘法器。改成依設位元展開的
移位加法樹,**DSP 7.5 → 5**,行為位元相同(300,012 值零不符驗證)。

## 4.3 偏態高斯核:量過了,不用再試

有人(包括 ConsensusAI)會建議用偏態/單邊漸降的核改善阻帶。**測過,全部更差:**

| 窗族 | 阻帶(論文定義 f ≥ 0.2 f_s) |
|---|---:|
| **none(對照組)** | **25.54 dB** |
| skew | 20.66 |
| tukey | 21.90 |
| expo | 21.61 |

對照組命中出貨值 25.44 dB → 搜尋有效。**機制**:漸降買阻帶的代價是過渡帶變寬,
通帶鎖死時無處可花(AVANZATO 2023 佐證)。

**順帶驗證了出貨核**:擬合得 ξ=5.300、σ₁=2.200、σ₂=8.801、σ₃=84.957,
與論文的 5.3 / 8.8 / 85 完全一致;重建阻帶 25.43 dB == ROM 的 25.43;
階躍下衝 18% 對論文的 17%。

# 5. 接下來做什麼(建議順序)

## 5.1 不需要等零件

1. **窗累加器瘦身** —— 每維兩個 44 位元是為「整窗都是滿刻度」的最壞情況留的,
   而那種窗**本來就會被拒收**。改飽和加法應可砍掉大部分的 +1152 Logic。
2. **`uncal` 自上電起算的絕對收斂時間** —— 現有的 4.00~4.09 s 是**同程序重複五次**
   的可重現值;另一次量到 6.74 s,因為錄製起點對齊不同。要寫進論文需獨立量。
3. **論文修訂** —— `01_paper/v25_revisions.md` 已寫好三節改寫加七則引用,
   **但檔頭有過期警告要先讀**(資源數字與 §IV-D 的誤觸發段落都要換成 v10 的)。
4. **秩統計版本(選做)** —— 中位數對污染不敏感,連守衛區都可省。
   先讀 **CADENAS 2015**(管線化中位數、整數位元切片、FPGA 面積省 40%、**不吃乘法器**)。

## 5.2 等零件(約 2026-09-20 到貨)

5. **感測 PCB 功耗實測** —— 它**獨立供電**,功率計串進去即可,**零風險**。
   一次量測就能把 Table II 的四行 datasheet 估算換成實測。
   注意 USB 功率計量的是**整板**(≈273 mW),不是 FPGA 的 37 mW;
   而且解析度約 5 mW,**量不到論文裡那些 0.4 mW 的增量**。
6. **AD5254 端到端下限** —— 四通道 256 階數位電位器(**訂單若寫 ADS5254 是 TI 的 ADC,要核對**)。
   - 介面是 **I²C 不是 SPI**,要寫新的 master(樣本間有 39,187 時脈,bit-bang 足夠)
   - **400k 到不了 1.74 MΩ 的工作點**,要串 1.5 MΩ 固定電阻
   - 串了之後:counts 2048~1638,約 1021 階 → **0.40 counts/階**(比需求細 12 倍)
   - 不串固定電阻則覆蓋按壓區(counts 6553~32767)
   - 目的:把合成掃描的同一組階梯**穿過真實 ADS** 再跑一次。
     兩者的差就是類比前端的貢獻,**那才是論文最終該報的下限**。

## 5.3 論文範圍(不要越界)

第二篇的題材(`01_paper/SUPPLEMENTARY_PLAN.md` 明列):

- 第一脈衝觸發的動態 profile 切換(設計在 `FINDINGS_2026-08-27.md` §7,**未驗證**,
  主要風險是換係數時的切換瞬態會被 flag engine 當成事件)
- 類型化診斷樣式表
- Mask 閘控傳輸的完整設計(**注意它會撞到 Manchester loss-of-lock 失效保護,需要心跳**)

# 6. 方法論(這些比任何單一數字重要)

1. **零誤觸發可以靠把門檻拉高白拿。靜止與下限必須一起量。**
   v8 只量靜止時看起來完美 —— 十分鐘 0 觸發、五輪 0、按壓 19/19 ——
   跑了合成下限才發現它聾掉三分之一。
2. **手做不出前端等級的刺激。** 前端解析度 1.45 ms,操作者變異 43 ms,**差 30 倍**。
   要求分級按壓時,19 次的峰值比只有 0.61。**任何前端特性化都不能靠手。**
   (文獻佐證:CHAUDHURI 2017,跨操作者時間解析度 17~37 ms。)
3. **先畫圖再解數字。** 用程式直接解會看不到東西。
4. **把中間量接到空 dim 上比對,不要靠讀程式碼。**
5. **挑靜止基準要用確定沒碰的錄音。** 語料庫前 3 秒的 var 高到 423,240,那不是靜止。
6. **量低頻雜訊絕不可分段去均值。**
7. **別拿多數群當正確值校正**(曾因此錯 2 倍)。
8. **模擬測不到硬體的失效。** 反向通道無逾時、冷開機、校正視窗、
   MIRROR 沒有 UART —— 四個都只有硬體會暴露。

## 7.4 幀格式

    byte 48  status = {4'b0, uncal, in_contact, is_slide, calibrated}
    dead map           1 = 該維校正時測到零變異(凍結/無感測器)
    dim 12             raw CH0(原始 ADC,不是 DoG)
    dim 13             synth step 索引(SYNTH=1 時)
    dims 14~17         slide_detect 內部量(DEBUG_TAPS=1 時)

只有 ch0 有感測器,所以正常的 dead map 是 **0x3FFF8**(dims 0/1/2 活著)。

# 6. 電感通道:狀態不明,而且是被遮蔽的(2026-09-02 查)

**這一節是給接手的人的警告:八月之後的所有工作都沒有碰過電感路徑,
而現行的錄音建置讓你連量都量不到。**

## 6.1 它的六個維度被蓋掉了

ch4 = L、ch5 = RP,對應 **dim 12–17**。而 `dsp_chain.v` 現在是:

```
RAW_DIM = 12   ← ch0 的原始樣本,蓋掉 ch4 的 DoG_fast
AUX_DIM = 13   ← 刺激產生器的 step 索引
DEBUG_TAPS -> dim 14/15/16/17  ← win_cnt / acc_cnt
```

**六個電感維度一個都不剩。** 2026-09-02 的 21 小時 soak 對電感通道沒有任何資訊。
要驗它必須先 `DEBUG_TAPS = 1'b0`,而且 **`MIRROR` 要是 1**(`MIRROR=0` 沒有 UART,
見 2.1),所以需要一次**專門的 `MIRROR=1 + DEBUG_TAPS=0` 建置** —— 那不是量產組態,
也不是量資源的那次建置,是第三種。

## 6.2 L 的「變異數為零」很可能已經解了,但沒人驗

論文 §IV-F 寫 L 是量化受限的:滿接觸只動 40 counts,校正窗內的雜訊
**四捨五入成整數變異數零**,旗標引擎因此做不出 z-score。

那是**七月**量的(電感錄音都是 `2026-07-03_LDC_*`)。而 **v5(2026-08-29)**
把校正變異數改成帶 4 個小數位:

```verilog
cal_var16 = cal_num >>> (2*CAL_SH - 4);   // = 16 * sigma^2
cal_dead  = (cal_var16 <= VAR_FLOOR);     // VAR_FLOOR = 0
```

判死的門檻因此從 **sigma^2 < 1** 降到 **sigma^2 < 1/16** —— **好 16 倍**。

## 6.5 幀格式改了:status bits 7:4(2026-09-02,**尚未建置**)

`status` 原本是 `{4'b0, uncal, contact, slide, 1'b1}`,上面四位元是空的。現在:

```
bit7 ads_err        bit6 ads_init_done
bit5 ldc_init_done  bit4 ldc_alive
bit3 uncal          bit2 contact       bit1 slide      bit0 常數 1
```

**bit4 是最重要的一個**,兩個條件同時成立才置位:

```verilog
ldc_alive = ldc_fresh && (ldc_chip_id == 8'hD4);
```

- `chip_id == 0xD4`:驅動**每圈重讀** CHIP_ID,抓 2026-07-31 那種 latch-up
  (所有暫存器讀 0xFF 但 SPI 還在跑)
- `ldc_fresh`:100 ms 內有 `data_valid`。**單看 CHIP_ID 不夠** —— 它是暫存器,
  驅動一停就保持舊值,過期的 0xD4 會被讀成活著。**兩個測試各抓一種故障:
  一個抓說謊的晶片,一個抓停掉的驅動。**

改動的檔:`ttcgs_board.v`(chip_id 接線 + staleness 計數器 + `health_w`)、
`ttcgs_sys.v`(新增 `health` 輸入埠)、`ttcgs_pnr.v`(接 `4'b0`)、
`log_frames.py`(檔頭文件)、新增 `check_health.py`。

**`ttcgs_sys` 多了一個必接的輸入埠** —— 任何其他實例化都要補 `.health(...)`,
沒有東西可報就接 `4'b0`。

`check_health.py <capture.csv>` 解這些位元,並且會**先判斷 bitstream 世代**:
2026-09-02 之前錄的檔 bits 7:4 恆為 0,工具會標成 `n/a` 而不是報成前端全死。

> **警告:以上 RTL 尚未建置也未燒錄。** 見 2.7 —— 改完 RTL 一定要重跑建置。
> 在跑過一次建置並在硬體上看到 bit4 置位之前,不要引用任何關於健康位元的行為。

## 6.6 RP 陷落已不存在,**不要搬 3-tap median**(2026-09-03 實測)

`top_dual.v` 的 median 註解寫得很清楚:**「With DIG_CONF=0x07 the RP channel throws a
ONE-SAMPLE dip on an exact 0.300 s cadence」**。而現行驅動是:

```verilog
ldc1101_spi.v:119   localparam LDC_HIRES = 1'b1;   // 1 = DIG_CONF 0xD7 + RP_SET 0x46
```

**設定從 0x07 換成 0xD7,瑕疵跟著消失。** 90 秒實測(只接 LDC)三個獨立證據:

```
3.333 Hz(=1/0.3s)在 DoG_fast 的功率 = 頻帶中位數的 0.2 倍   ← 比背景還低
|x| > 6 sigma 的樣本 = 0 個,孤立單樣本 = 0 個
估計器 mask 0% / uncal 0%                                  ← 沒有鎖死
```

**而 median 是有代價的。** `top_dual.v` 自己警告:

> Bypass them for transient work — **they exist to kill single-sample spikes, which is
> exactly what a real impact looks like.**

**為一個不存在的問題加一個會刪掉真實事件的濾波器,是淨損失。**

### 教訓(這是同一天犯的第二次)

我先用七月量到的陷落做離線模擬,結論是「median 比斜率限幅好(803 窗 vs 508)」——
**模擬沒錯,錯在沒先確認那個瑕疵今天還在不在。** 同一天稍早也踩過一次:偵測下限的
55 counts 那個點,是把前一階慢帶尾巴當成刺激。

> **拿舊條件下的觀察當成現在的前提 —— 引用任何跨版本的實測前,先確認產生它的組態還在。**

### 順帶確立的兩件事

1. **「限制估計器,不限制偵測器」這個原則成立。** 估計器要穩健、偵測器要忠實,兩者需求
   相反,所以要分兩條路。`top_dual` 那條警告是獨立的印證。
2. **開機那 20 秒暫態的機制查清楚了。** `mu` 是每個校正窗更新一次(不是連續 EWMA),
   離線模擬顯示它**一個窗 0.70 秒就能收斂**。所以慢的不是 mu,是**窗完成不了**:
   dim17 持續觸發 → guard 暫停累積 → 看門狗每 3 秒強制完成一個 → 約七輪才爬上去。
   **那是看門狗在真實硬體、真實通道上運作的直接證據**,比合成的持續刺激測試更硬。

### 斜率限制的三個應用,全部量過,全部否定

| 應用 | 結果 |
|---|---|
| 限制強制接受的跳幅 | **不必** —— 四種佔空比下強制接受**一次都沒觸發**(guard 讓污染窗填不滿,走不到拒收路徑);加 5% 限制反而讓估計值更差(0.70~0.78x → 0.63~0.67x) |
| 除突波 | **不必** —— 見上 |
| 限制 mu 的爬升 | **有害** —— 0.70 秒 → 50% 限制 17.8 秒、20% 以下永不收斂 |

**未量到:** 限制基線吸收**慢速漂移**的速度(慢端的 target masking)。今天只錄到暖機
暫態(RP 90 秒漂 +126 counts,約 0.5%),**穩態漂移仍未量**。

# 7. ADS 「壞掉」的真相(2026-09-03/04):地線位置 + 電容過大

**結論先講:兩塊板的 ADS 和 LDC 都是好的。七月記錄的「A 板 ADS 好 / B 板 ADS 死
(DRDY path)」是誤診。** 現在雙模態同時運作:壓阻 **634 Hz**、電感同時活著、
零 CRC 錯 —— 錄音 `data/2026-09-04_ads_retry_raw.csv`。

## 7.1 兩個根因

**(a) DGND 線插在哪一顆旁邊,決定哪一顆能用。**

地線不是「電位參考」,是**回流路徑**。地線接在 LDC 那側時,ADS 的數位切換電流要
繞一大圈才回得去,而一條細跳線約 **1 nH/mm**(10 cm ≈ 100 nH)。SPI 邊沿的 di/dt
打在這個電感上,ADS 的**本地地**就跟 FPGA 的地產生真實電位差 —— 所有邏輯準位的
判定基準都偏掉,POR 判定的「電源相對於自己的地」也偏掉。

> **這解釋了「兩塊同批次的板子各壞一邊、而且不能互換」** —— 不是兩個獨立缺陷,
> 是同一條地線插在不同位置:**地線旁邊那一顆正常,另一顆回流繞遠路就「壞掉」。**

**(b) LDO 輸出的 2 × 10 µF 太大,拖慢上電斜率,ADS 的 POR 不觸發。**

`LT1763` datasheet:**最小輸出電容 3.3 µF、ESR ≤ 3 Ω**;BYP 腳有 100 pF 時建議
**4.7 µF**。原本 20 µF 是最小值的六倍。實測三態:

```
20 µF  ->  上電太慢  ->  POR 從未觸發  ->  永遠不啟動
 0 µF  ->  夠快但 LDO 迴路不穩  ->  跑了 474 次轉換後停止
4.7 µF ->  兩個條件都滿足        ->  32 秒零凍結,穩定 20 SPS
```

**兩個改動都做了,無法乾淨分離各自的貢獻。但 (a) 解釋的歷史更多**(尤其兩塊板的
不對稱),(b) 有明確的實測三態。

## 7.2 症狀為什麼會長成那樣

晶片沒完成 POR 時,**數位介面有電、轉換核心沒啟動**:

| 症狀 | 成因 |
|---|---|
| SPI 偶爾回 `ID=0x0C`(約 12%) | 介面由外部 SCLK 驅動,不需要晶片的系統時脈 |
| DRDY 零邊沿、FSM 卡 `S_WAITDR` 100% | 核心沒啟動 |
| DOUT 浮空在 ~1.71 V 不被驅動 | 同上 |
| **重焊三次完全沒有改變** | **焊接從來不是根因** |

## 7.3 途中真實存在、但不是根因的

* **DIN(FPGA pin 27)虛焊** —— 是真的,已修好(兩端都能跳 0↔3.3 V)
* **CS → GND 480 Ω 漏電** —— **還在**,但實測不影響運作(634 Hz 穩定)。
  最可能是免洗助焊劑殘留;有空用異丙醇洗掉即可,不急。

# 8. 壞掉的 CS 繞過去了 —— 雙模態同時運作(2026-09-04 下午)

B 板 ADS 的 CS 是**永久箝位**(1.01V @ DRIVE=8、1.35V @ DRIVE=24,V_IH 需 2.31V;對地 480Ω,好板是 305kΩ~1MΩ;latch-up 解除程序無效)。但**晶片本身是好的**,用邏輯繞過即可,不必換板。

## 8.1 繞法(`ads114s08_spi.v`,`CONT_MODE=1`)

| 做法 | 為什麼 |
|---|---|
| **CS 恆低** | 箝位讓 CS 到不了高準位,但**低就是選中狀態** —— 恆低反而可用 |
| **START 腳脈衝觸發轉換**(`STARTP_CLKS=27` ≈ 1µs) | 單次模式下一次脈衝 = 一次轉換,與 SPI 的 `0x08` 語意相同,但**不經過壞掉的網路** |
| **保留單次模式,不改連續轉換** | 驅動依賴的兩件事只在單次模式驗證過:一個 START 一次乾淨轉換(無連續模式邊界競爭);轉換完 DRDY# 保持低且結果已驅動在 DOUT 上 —— 這才是「16 clock 不送 RDATA」能成立的原因 |
| **設定暫存器寫入後讀回驗證並重試** | CS 不可靠時不能假設寫進去了 |
| **每 4096 次轉換複查 DATARATE(金絲雀)** | CS 恆低時沒有東西能偵測失步,靜默漂走的轉換器會一直吐出看似合理的數字 |

## 8.2 最大的坑:CS 恆低 = 位元組邊界永遠不會重新對齊

ADS 的位元組計數**從 CS 下降沿起算**,CS 上升是唯一的重新同步點。CS 永遠不上升,**一旦偏移就是永久的**。而 **FPGA 重新設定時 I/O 會經過未定義狀態,SCLK 會抖出雜散邊緣**。

**症狀特徵(用來區分兩種失效):**

- 鏈路邊際不穩 → **隨機**失敗
- **位元組邊界丟了 → 失敗而且黏著**

實測就是後者:正常跑了兩次 → 某次重燒後死掉 → **接著連續四次重燒全死**。

**解法:搜尋那 8 個對齊。** 讀回驗證失敗就多打**一個** bit(`S_NUDGE`)再重來,最多 8 次必中;每輪前先送 **3 個位元組的 0x00**(`S_FLUSH`)—— NOP 就是 0x00,**全零串在任何對齊下都解碼成 NOP**,所以能在不知道邊界在哪的情況下清掉半截命令。加上之後**三次重燒全部起來**。

原本的重試迴圈重試了 **40 次同一個對齊**,當然全錯。**重試要重試在會變的東西上。**

## 8.3 讀取位元數是 24 不是 25

檔頭 BUG 2 寫「讀寫都要 useful_bits+1」—— 那是**舊引擎**的。取樣邊緣修好之後,引擎自己的註解寫著 `every "+1" is gone`,而底下三個能動的 WREG 都是 24、RDATA 是 16。從 `ads_regcheck.v`(跑舊引擎)抄 25 過來,**在 CS 恆低下 25 = 3 位元組 + 1 bit,等於每次交易都自己製造一次永久偏移**。金絲雀抓到的第一個錯是自己寫的。**看能動的路徑,不要看檔頭註解。**

# 10. 量化受限的誤觸發 —— 門檻下限(2026-09-04 夜)

§9 把 ADS 雜訊降了 13 倍之後,壓阻通道變成量化受限,靜止誤觸發從 0 變成 50%。修法與過程:

## 10.1 機制

`d0` 全段只剩 **5 個值(−2..+2)**,逐窗變異 0.16–0.72。`var16 = 2` 時門檻是 `25×2/16 = 3.125`,而通道自己的 ±2 量化階給 `f² = 4` —— **直接越過**。5σ 乘上一個小於 1 LSB 的 σ 比 1 LSB 還小,門檻就不再有意義。

## 10.2 兩個踩到的坑

**坑一:ε 不適用於這份實作。** 2026-07 驗證過的「逐帶 epsilon `z=f/(σ+ε)`,ε=0.3」是在**線性域**比較的前提下推的(那時 ε 只是一個加法)。**這個引擎在平方域比較**(`f² > N_SQ·σ²`),`(σ+ε)²` 要開根號,反而是**變異數/門檻下限便宜**(compare + mux)。而且 **ε=0.3 的數值也不能搬** —— 它是配 LDC 的 L 通道、σ 塌到 0.01–0.05 的情況,比這裡小一到兩個數量級。

**坑二:門檻有兩個寫入點,單位還不一樣。**

```verilog
441:  else if (s2_final && !cal_hot)        threshold[] <= cal_thr;    // 一次性校正,16σ² 單位
442:  else if (s2_roll && w_full && acc_ok) threshold[] <= thr_win;    // 滾動更新,σ² 單位
```

只對第一個設下限,**誤觸發率完全沒變(34%)** —— 滾動路徑每 512 樣本就把門檻覆蓋回去。因為兩邊單位不同(`cal_var16` 是 16σ²,`new_var = w_sum_n >> CAL_SH` 是 σ²),正解是**對門檻本身設下限**,一個常數、兩個寫入點都套。

## 10.3 現行做法

```verilog
parameter VAR_MIN16 = 16;                              // σ 下限 = 1 LSB
localparam signed [39:0] THR_MIN = (N_SQ*VAR_MIN16)>>>4;   // = 25 counts²
```

SoC 的 `lut_thr` 寫入**刻意不套下限** —— 軟體明寫的門檻就照它說的算。`cal_dead` 也仍用未設限的 `cal_var16`,所以真正死掉的通道還是會被標死,不會被墊高的變異數當成活的。

取 1 LSB 有依據:實測純量化造成的 σ 是 0.4–0.85 LSB,門檻 5 counts 對純量化跳動留 5.9σ 餘裕。

## 10.4 結果(`board_v22_thrmin.fs`,封存 `impl_archive/2026-09-04_board_v22_refoff_thrmin/`)

```
Logic 6199/8640 72% | Register 3456 | DSP 5/10 | 0 錯誤
41,452 幀 0 掉幀 | raw sd 1.01 | d15 sd 27.7 | ldc_alive 100.00%

             ↑ 拔掉充電器的那一刻
```

**協定:量任何雜訊或誤觸發之前,拔掉筆電充電器。** 兩秒鐘的動作,37 倍的差別。**演示用行動電源**,完全脫離市電參考。

⚠ **2026-09-04 之前所有的雜訊與誤觸發數字,充電器狀態都沒有記錄**,因此都是被混淆的。引用前要確認條件或重量。

## 13.3 沒供電的週邊,訊號線一定要一起拔

FPGA 把訊號打進沒供電的晶片,電流經訊號腳的 ESD 二極體灌進它的 VCC 軌 —— **等於用訊號線幫它部分供電**。一天踩兩次:

| 情況 | 症狀 |
|---|---|
| B 板 LDC SPI 線接著、LDC 沒供電 | raw sd 多 **1.66 倍** |
| SG90 訊號線接著、伺服沒供電 | **基線從 1600 跳到 3400** |

**基線位移比雜訊更陰險** —— 幀率、CRC、LED 全部正常,只有數值悄悄偏掉,而校正會把偏掉的基線當成正常值學進去。

## 13.4 新的天花板

排除兩者後 raw sd **1.503**,範圍 1608..1622,**只有 15 個相異值**。LSB 是 1 count,所以**系統現在是 ADC 量化受限,不是雜訊受限** —— 再壓雜訊沒有用,要再進步得靠解析度或增益。

# 14. 接觸輸出:三條帶沒有一條在回答「現在有沒有接觸」(2026-09-09)

## 14.1 問題

實測 70 次按壓(真實接觸中位 130 ms),各訊號報出來的接觸長度:

| | 起點偏差 | 終點偏差 | **長度偏差** | sd |
|---|---|---|---|---|
| d0 快帶 | +0.3 ms | +56.0 | +55.5 | 33.7 |
| d1 慢帶 | +0.3 ms | −110.9 | −116.0 | 18.5 |
| d2 持續帶 | +0.3 ms | +371.2 | **+370.7** | 5.9 |

**d2 的 +371.2 ms 就是 256-tap 的 FIR 視窗長度**(256/689.5 = 371.3 ms,對到小數點)。按壓要等它從緩衝區滑出去才停 —— **跟門檻無關、跟訊號衰減無關,唯一的旋鈕是 tap 數**。後果:111 ms 的快按在 d2 上是 481 ms,看起來像持續接觸。

## 14.2 解法:raw 進空維度,取交集

**raw 本身的邊緣很銳利**(上升 6.5 ms、下降 4.4 ms),而 `SINGLE_CH=1` 讓 ch1/2/3 的**九個維度永遠是死的**。把 raw 用同一套自適應門檻(ABS、×16 刻度)餵進 **dim 3**,零硬體成本。

**接觸 = `mask[2] & mask[3]`**

| | 命中 | 長度偏差 | sd | 非接觸 74 秒 |
|---|---|---|---|---|
| dim3 raw 單獨 | 70/70 | −0.2 ms | 4.7 | 0 幀 |
| **交集 2&3** | **70/70** | **−0.3 ms** | **4.9** | **0 幀** |

**+370.7 ms → −0.3 ms。** 先用 `press_v30.csv` 離線模擬過(預測 +0.0 / sd 7.7),實測比預測還好。

**交集對時序沒有貢獻** —— raw 的區間整個包在 d2 裡,取交集後 raw 決定兩端。它貢獻的是「兩者都要同意」:離線模擬裡 raw 單獨在 73 秒非接觸段漏了 1 幀,交集是 0。

**三條帶的核、通帶、刻度、門檻一律沒動,論文的多尺度主張不受影響。** 接觸是多出來的第四個輸出,不是改寫。

## 14.3 實作坑

- `dsp_chain` 加 `F_RAW` 狀態,只在 `feed_ch==0` 之後觸發
- **`raw_x16` 要飽和保護**:raw×16 在按壓時超過 16 位元,夾住對 ABS 無害
- **ch1 的 `F_FAST` 必須跳過** —— `feed_ch*3+0` 在 ch1 時也是 dim 3,兩個訊號輪流餵同一維會毀掉它的校正
- LED 與伺服的持續帶改吃交集,**放開就熄**,不再拖 371 ms

# 15. BUILD_ID:幀裡的燒錄識別碼(2026-09-09)

**幀的 dim 4 帶著 bitstream 的版本碼**,`log_frames.py` 第一幀就印:

```
bitstream BUILD_ID = 0x0935
```

十六進位、一眼可讀:`0x0935` = 09 月第 35 版。定義在 `dsp_chain.v` 的 `parameter [15:0] BUILD_ID`,經 `ttcgs_sys` 傳下去。**每次建置要跟著 `.fs` 的版號一起改。**

**為什麼需要:這塊板有三種方式會跑到「不是你剛建置的東西」,而且都不會報錯。**

1. **SRAM 燒錄斷電就沒**,FPGA 自動重載 flash 裡的舊 bitstream
2. **按 RESET 從內建 flash 重載**,不是重跑 SRAM 裡的
3. **Gowin 的 `Verify Failed at 0` 是假警報**,兩個方向都不能信

前兩個在 2026-09-05 都實際發生過(「伺服沒反應」是因為建置了卻沒燒;LED 行為對不上是因為跑的是 flash 裡的舊版)。第三個在 09-09 用 BUILD_ID 正面解決了:**冷開機後讀到 0x0935,證明 flash 確實寫進去了。**

dim 4 是 ch1 的慢帶,`SINGLE_CH=1` 之下永遠是死的,所以零成本。同理 dim 3 已被 raw 佔用(見 §14)。

**現行出貨:`board_v35_bid.fs`,已燒內建 flash,冷開機驗證通過**(690.1 fps、0 掉幀、dead 0x3FFF0、dims 0-3 全活、靜止 0 誤觸發 / 17,256 幀)。

## 16.2 v30:先相減再飽和(差分帶也能用細刻度)

§12 的結論是「細刻度只能給 G_s3」,那是因為當時**先飽和再相減**。正解是把 `g_wide` 保留不飽和、**差分算完才 `sat16` 一次** —— 要活下來的是**差**不是**項**。

但過程中選錯了刻度,值得記:

**⚠ 用 2^6 反而更糟。** d1 峰值約 22,000 counts,×64 的飽和點只有 512,**暫態中段兩個 ROC 運算元都夾在 32767,`x[n]−x[n−10]` 讀成 0**。症狀是 mask 只在「穿越飽和帶」的瞬間出現,而**縮短的觸發看起來像改善,其實是資訊遺失** —— 我一度把它寫成「尾巴縮短 15 倍」。

**⚠ G_s3 的刻度上限由直流決定,不是由暫態。** 它的靜止值就是基線(約 1613 counts),×64 之後是 103,232,`sat16` 夾在 32767,`x−mu` 恆為 0 —— 實測 **d2 在 72 次按壓中 0/72**,而 d0/d1 完全正常。**刻度上限 = 32767/1613 ≈ 20 倍。**

最後定在 **2^4 全部共用**:d1 的門檻 0.53 counts 在 2^4 已經高於 0.31 的下限(所以是自適應的),而飽和點高 4 倍。**2^6 沒有多買到任何靈敏度。**

實測 v30:三帶延遲全部 2.90 ms(理論下限)、三帶全中 72/72、非接觸段 mask 3 幀/73 秒、靜止 30 秒 0 幀。
