# 1. 這個專案在做什麼

生物擬態觸覺前端,跑在 Tang Nano 9K(GW1NR-9C,27 MHz)上。

**核心主張(TTCGS):** 在感測層就把時間結構編碼成三個尺度的 Difference-of-Gaussians
(對齊 RA-I / SA-I 機械受器頻帶),輸出 18 維特徵向量加一個 18 位元的注意力遮罩,
**把「資料到決策」的映射留給下游**。論文的立場叫 **encode and defer**。

    raw -> DoG 三尺度 -> z-score flag -> 18-bit mask -> 51-byte frame + CRC
                                                     -> Manchester 單線 -> SoC
                                     <- 反向通道改寫門檻(閉環)

目標:preprint(TechRxiv/arXiv)→ IEEE Sensors Journal,兩段式。

# 2. 會浪費你好幾天的十個坑

> 這一節不是理論,是**每一條都真的踩過**。

### 2.1 `MIRROR=0` 完全沒有 UART 輸出

`ttcgs_board.v` 的 `MIRROR=0` 分支是 `assign uart_tx = 1'b1;` —— **綁死高電位**。
論文報資源的那個組態**從主機端量不到任何東西**,幀只走 Manchester 單線鏈路。

燒了 MIRROR=0 之後 `log_frames.py` 讀到 **0 幀**,那**不是故障**。

| 組態 | 用途 | 可量測 |
|---|---|---|
| MIRROR=0 | 論文報資源 | **否** |
| MIRROR=1 | **所有實測** | 是 |

**所有實測資料(soak、語料庫、下限)都是 MIRROR=1 錄的。**

### 2.2 `Verify Failed at 0` 是假警報

每次燒 flash 都會出現。**真憑據是 User Code 有沒有隨 bitstream 改變**
(v6 `0x468B` / v10 real `0x601A` 等)。不要為此重燒或懷疑 flash 壞了。

### 2.3 絕不要對這塊板跑 Zadig

libwdi 驅動會跟 FTDI 打架,把裝置弄成 `CM_PROB_FAILED_START`(code 10),
要手動清 `oem*.inf` 才救得回來。**拔插後介面 B 出問題就換一個 USB 埠。**

### 2.4 燒錄一律用 `flash.ps1`

`programmer_cli` 少了 `--location` 會**永久卡死**(Ctrl+C 也不理),
殘留行程會鎖住 USB。`flash.ps1` 會自動探測 JTAG 通道。

    .\flash.ps1 -Check                    # 只讀 device code
    .\flash.ps1 -Fs xxx.fs                # 燒 SRAM(斷電即失)
    .\flash.ps1 -Fs xxx.fs -Flash         # 燒內建 flash(過夜量測用這個)

### 2.5 Gowin 所有 target 共用一個 `impl/`

換一個 top 去合成就會**無聲地覆蓋**。**跑完立刻歸檔**,而且
**判定成功要看錯誤數,不要看 `project.fs` 存不存在**(曾經建置失敗但腳本
照印成功訊息加一份陳舊報告的數字)。

### 2.6 `check_stream.py` 不能讀量產韌體

它是給 `dual_*` 那組**文字**輸出的 bitstream 用的。量產 `ttcgs_board` 送
**51 位元組二進位幀**,要用 `log_frames.py`。拿 check_stream 去讀會看到
「非可列印 92%」—— 那是正常的。

### 2.7 改完 RTL 一定要重跑建置(這錯犯了三次)

資源數字錯過三次,每次都是因為改了 RTL 卻引用舊報告。
**引用資源前也要確認 `DEBUG_TAPS=0`**(`dsp_chain.v`)。

### 2.8 Verilog 有號性(踩過兩次,其中一次讀了四次程式碼沒找到)

- **串接永遠是無號的** —— `{a,b}` 不管 a、b 有號無號,所以 `>>>` 會變邏輯右移
- **`~x + 1'b1` 會把整個三元式降為無號** —— 負數被當無號平方

除錯方法:**把中間量接到空的 dim 上比對**(dims 14~17,`DEBUG_TAPS=1`),
不要靠讀程式碼。

### 2.9 定點移位:先看被移位的數有多大

    thr <- thr + ((target - thr) >>> 12)      // 災難

門檻只有 ~118,`>>>12` 讓**正差變 0、負差變 −1**(算術右移向 −∞),
門檻 **0.17 秒歸零**,88~99% 的幀觸發。修法是累加器加寬當小數。

同類錯誤:**把編譯期常數寫成 `*`**。`parameter N_SQ = 25` 寫成
`N_SQ * cal_var16` 讓工具推導出一顆真乘法器,**白丟 2.5 個 DSP macro**。
改成依設位元展開的移位加法樹後 DSP 從 75% 回到 50%。

### 2.10 heredoc 會弄壞 Verilog patch

bash heredoc 在這個環境下反覆失敗。**要改多行 RTL 就把 Python patch 寫成檔案再執行**,
不要用 `python - << EOF`。

# 4. 今晚(08-29/30)做完的事,以及為什麼那樣做

## 4.1 自適應雜訊估計 v6 → v10

**根因(可計算):** `CAL_N=512` 對 d2(G_σ3,自相關時間 **τ=84 幀**)
只有 **~6 個獨立樣本**。χ² 六自由度 → σ 估計 0.52×~1.45× →
**標稱 5σ 實際落在 2.6σ~7.3σ**。實測六次開機 0.007%~0.083%,與模型吻合。

**分佈是高斯的**(kurtosis 2.9)—— **錯的是估計器不是模型。**

演進(每一版都是被前一版的實測失敗逼出來的):

| 版本 | 做法 | 壞在哪 |
|---|---|---|
| v6 | 一次性校正 + 5σ | 跨開機 0~0.083% |
| v7 | 每樣本 EWMA(第一版) | **定點移位捨入,0.17 秒歸零** |
| v8 | 每樣本 EWMA(修好) | **次閾值訊號自我遮蔽,下限 100%→67%**,DSP →70% |
| v9 | **整窗接受/拒收** | 1/5 輪開機有 80 ms 暫態 |
| **v10** | **+ 2σ² 保守種子 + `uncal` 撐到收斂** | **目前無已知問題** |

**v8 為什麼賠掉下限(通則):** 守衛區只在**觸發**時武裝,所以**次閾值刺激沒有守衛** ——
能量進入雜訊估計、推高門檻、把自己推得更低於門檻。正回饋。
靜止測試(沒訊號)和按壓測試(訊號大到必觸發)**都看不到**。
雷達裡叫 **target masking**。

**v9 的關鍵是「能不能拒絕」:** 連續平均無法拒絕,**整窗取捨可以**。
而且**拒收判準必須相對** —— 55 counts 的按壓只貢獻 700~1400 counts²,
遠低於 `VAR_CEIL=20000`,卻是靜止 4.7 的 **300 倍**。

**v10 的兩處:** 種子取 **2σ²**(種子誤差對稱但後果不對稱:偏低誤觸發、
偏高只是短暫遲鈍),`uncal` 撐到累積 8 個接受窗。

`uncal` 的**語意已改**:從「一次性校正做完了」變成「**估計已收斂到可信**」。
論文 §III-E 要跟著改。

細節:`DATA/ADAPTIVE_BASELINE_2026-08-30.md`

## 4.2 常數乘法強度削減

`parameter N_SQ` 寫成 `*` → 工具推導出 40×5 真乘法器。改成依設位元展開的
移位加法樹,**DSP 7.5 → 5**,行為位元相同(300,012 值零不符驗證)。

## 4.3 偏態高斯核:量過了,不用再試

有人(包括 ConsensusAI)會建議用偏態/單邊漸降的核改善阻帶。**測過,全部更差:**

| 窗族 | 阻帶(論文定義 f ≥ 0.2 f_s) |
|---|---:|
| **none(對照組)** | **25.54 dB** |
| skew | 20.66 |
| tukey | 21.90 |
| expo | 21.61 |

對照組命中出貨值 25.44 dB → 搜尋有效。**機制**:漸降買阻帶的代價是過渡帶變寬,
通帶鎖死時無處可花(AVANZATO 2023 佐證)。

**順帶驗證了出貨核**:擬合得 ξ=5.300、σ₁=2.200、σ₂=8.801、σ₃=84.957,
與論文的 5.3 / 8.8 / 85 完全一致;重建阻帶 25.43 dB == ROM 的 25.43;
階躍下衝 18% 對論文的 17%。

# 5. 接下來做什麼(建議順序)

## 5.1 不需要等零件

1. **窗累加器瘦身** —— 每維兩個 44 位元是為「整窗都是滿刻度」的最壞情況留的,
   而那種窗**本來就會被拒收**。改飽和加法應可砍掉大部分的 +1152 Logic。
2. **`uncal` 自上電起算的絕對收斂時間** —— 現有的 4.00~4.09 s 是**同程序重複五次**
   的可重現值;另一次量到 6.74 s,因為錄製起點對齊不同。要寫進論文需獨立量。
3. **論文修訂** —— `01_paper/v25_revisions.md` 已寫好三節改寫加七則引用,
   **但檔頭有過期警告要先讀**(資源數字與 §IV-D 的誤觸發段落都要換成 v10 的)。
4. **秩統計版本(選做)** —— 中位數對污染不敏感,連守衛區都可省。
   先讀 **CADENAS 2015**(管線化中位數、整數位元切片、FPGA 面積省 40%、**不吃乘法器**)。

## 5.2 等零件(約 2026-09-20 到貨)

5. **感測 PCB 功耗實測** —— 它**獨立供電**,功率計串進去即可,**零風險**。
   一次量測就能把 Table II 的四行 datasheet 估算換成實測。
   注意 USB 功率計量的是**整板**(≈273 mW),不是 FPGA 的 37 mW;
   而且解析度約 5 mW,**量不到論文裡那些 0.4 mW 的增量**。
6. **AD5254 端到端下限** —— 四通道 256 階數位電位器(**訂單若寫 ADS5254 是 TI 的 ADC,要核對**)。
   - 介面是 **I²C 不是 SPI**,要寫新的 master(樣本間有 39,187 時脈,bit-bang 足夠)
   - **400k 到不了 1.74 MΩ 的工作點**,要串 1.5 MΩ 固定電阻
   - 串了之後:counts 2048~1638,約 1021 階 → **0.40 counts/階**(比需求細 12 倍)
   - 不串固定電阻則覆蓋按壓區(counts 6553~32767)
   - 目的:把合成掃描的同一組階梯**穿過真實 ADS** 再跑一次。
     兩者的差就是類比前端的貢獻,**那才是論文最終該報的下限**。

## 5.3 論文範圍(不要越界)

第二篇的題材(`01_paper/SUPPLEMENTARY_PLAN.md` 明列):

- 第一脈衝觸發的動態 profile 切換(設計在 `FINDINGS_2026-08-27.md` §7,**未驗證**,
  主要風險是換係數時的切換瞬態會被 flag engine 當成事件)
- 類型化診斷樣式表
- Mask 閘控傳輸的完整設計(**注意它會撞到 Manchester loss-of-lock 失效保護,需要心跳**)

# 6. 方法論(這些比任何單一數字重要)

1. **零誤觸發可以靠把門檻拉高白拿。靜止與下限必須一起量。**
   v8 只量靜止時看起來完美 —— 十分鐘 0 觸發、五輪 0、按壓 19/19 ——
   跑了合成下限才發現它聾掉三分之一。
2. **手做不出前端等級的刺激。** 前端解析度 1.45 ms,操作者變異 43 ms,**差 30 倍**。
   要求分級按壓時,19 次的峰值比只有 0.61。**任何前端特性化都不能靠手。**
   (文獻佐證:CHAUDHURI 2017,跨操作者時間解析度 17~37 ms。)
3. **先畫圖再解數字。** 用程式直接解會看不到東西。
4. **把中間量接到空 dim 上比對,不要靠讀程式碼。**
5. **挑靜止基準要用確定沒碰的錄音。** 語料庫前 3 秒的 var 高到 423,240,那不是靜止。
6. **量低頻雜訊絕不可分段去均值。**
7. **別拿多數群當正確值校正**(曾因此錯 2 倍)。
8. **模擬測不到硬體的失效。** 反向通道無逾時、冷開機、校正視窗、
   MIRROR 沒有 UART —— 四個都只有硬體會暴露。

## 7.4 幀格式

51 位元組。`d0..d17` 為 18 維特徵(每維 16 位元有號),然後:

    byte 48  status = {4'b0, uncal, in_contact, is_slide, calibrated}
    dead map           1 = 該維校正時測到零變異(凍結/無感測器)
    dim 12             raw CH0(原始 ADC,不是 DoG)
    dim 13             synth step 索引(SYNTH=1 時)
    dims 14~17         slide_detect 內部量(DEBUG_TAPS=1 時)

只有 ch0 有感測器,所以正常的 dead map 是 **0x3FFF8**(dims 0/1/2 活著)。

它**不能**分類手勢 —— 那條路試過兩次,兩次都是量到力道或黏滑摩擦而不是類別,

除非有剪力或空間資訊(文獻裡救得回分類的手段全都需要那些,而我們沒有)。
