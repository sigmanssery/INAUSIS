# 2026-08-27 量測與模擬發現

## 1. DoG_fast 與 MA 差分在通帶內幾乎等效 ← 最重要

延遲後的 causal DoG 快分支 (sigma1=2.2, sigma2=8.8) 與中心匹配的 MA4-MA15:

    Hz      DoG_fast   MA差分       (各自正規化到峰值)
    0.5      0.029     0.025
    5        0.281     0.240
    20       0.880     0.821
    35       0.999     0.997      <- 兩者峰值同在 33 Hz
    60       0.821     0.604

**通帶形狀差異在 7% 以內,而 MA 的絕對增益還高 1.7 倍**(35 Hz 正弦:727.6 vs 419.1)。

**推論**:多尺度編碼的偵測優勢**不是**來自高斯核在單一尺度上比較好,而是來自
**涵蓋了 DoG_slow 所在的 1-10 Hz**,那是單一差分濾波器沒有覆蓋的區間
(該頻段 DoG_slow 增益 0.88-0.98,MA 差分只有 0.025-0.24)。

高斯核仍有的價值,但要講對是哪一種:
* **帶外抑制** 延遲 DoG -25.4 dB vs MA 差分 -12.3 dB(差 13 dB)
* **尺度間不產生新極值**(高斯獨有,使跨尺度比較有意義)
* **不是** 通帶內的效能

這**證實**稿件中「增益來自 multi-scale decomposition rather than the kernel」那句。

## 7. 延遲偏移 D 的最佳性(2026-08-27 追加)

固定通帶(峰值 ~33 Hz、-3 dB 14-70 Hz @ 689 SPS)、對每個 D 重新求解 (s1,s2):

    D     s1     s2    延遲(ms)  帶外抑制
    0.0   2.46   7.80    5.42    -11.2
    2.0   1.80   7.47    6.77    -15.0
    4.0   2.06   7.83    9.88    -18.7
    5.3   2.20   8.80   11.17    -25.5   <- 最佳
    7.0   2.22  10.60   11.84    -24.6
    9.0   2.04  12.81   12.97    -22.6
    12.0  1.30  16.29   16.15    -11.2

**D = 5.3 是最佳值**,超過之後抑制反而變差(固定通帶會逼 s2 變大,形狀劣化)。
論文原本的參數選擇因此從「試出來的」變成「推導出來的」。

可用的取捨範圍是 D in [0, 5.3]:延遲 5.4 -> 11.2 ms(2.1 倍)換抑制 -11.2 -> -25.5 dB
(14.3 dB)。若要做執行時可選的 profile,**兩組就夠**:

    fast     D=0    s=(2.46, 7.80)   5.4 ms   -11.2 dB   onset/反射
    default  D=5.3  s=(2.20, 8.80)  11.2 ms   -25.5 dB   持續段

實作代價:係數 ROM 768 -> 1536 entries,選擇訊號 1 bit。反向通道現有協定
([dim_id][value])可用保留的 dim_id 承載 profile 選擇,lut_parser.v 加數行。
注意 dog_fir_multi.v 的 coef_rom 目前是 $readmemh 綜合時載入、執行時唯讀。

**未驗證**:第一脈衝觸發的動態切換。主要風險是切換瞬態——FIR 有 33 個有效
taps,換係數時緩衝內仍是舊資料,輸出不連續會被 flag engine 看成事件。


## 8. 正規化判別量:用總能量而非另一個帶通當分母(2026-08-27 追加)

> ### ⛔ 已推翻(2026-08-28)—— 本節的預測做了獨立驗證,結果是否定的
>
> 本節結尾寫著「必須用第二場當獨立驗證集重現,才能寫進論文」。
> **第二場做了,沒有重現。**
>
> `fast/g3` 與接觸力道的相關是 **r = −0.912**,力道解釋它 **83%** 的變異
> (30 筆,log-log 回歸斜率 −1.63)。**力道配平之後 C 對 G 只差 0~8%**
> (C5 vs G3 在 |g3| 15150/15626 下是 0.125 / 0.125,差 0%)。
>
> 下表「C 0.079 對 G 0.301、3.82 倍、逐筆完全不重疊」之所以成立,
> 是因為那一場的 C 與 G 剛好按在不同的力道上 —— **量到的是力道,不是時間結構。**
>
> 分母改用 `G_s3`(近似總能量、隨力道增長)而分子不隨,正是把力道放大進比值的
> 機制。後來找到的力道無關版本是 **`RMS(raw − G_s1) / RMS(DoG_fast)`**
> (分子分母同訊號兩頻帶,r 與力道 +0.01),見 `SLIDE_DETECT_2026-08-28.md` ——
> 但**它的分類主張也沒有複現**,見該文件開頭的警示。
>
> 詳見 `FINDINGS_2026-08-28_force-confound.md`。**本節下方的數字不可引用。**

**問題**:現行的 fast/slow 是兩個帶通相除。接觸與釋放是寬頻邊緣,兩個帶通都會被
激發,比值因此被壓縮 —— 這是 C 對 G 分不開的直接原因。

**修正**:拿帶通去比**總能量**,得到「能量落在帶內的比例」,對整體振幅不敏感。

在 2026-08-27 第一場(MRE 貼邊固定,五類 x 4)的 C 對 G 上:

    判別量            C        G      比值   分離度
    fast/slow      0.176    0.241    1.37x   2.30 sigma   <- 現行
    f/(f+s)        0.150    0.194    1.30x   2.37 sigma
    f/(f+notch)    0.068    0.156    2.30x   4.50 sigma   <- 陷波
    fast/g3        0.079    0.301    3.82x   3.98 sigma   <- 最佳且免費

逐筆完全不重疊:C = 0.046/0.063/0.073/0.083,G = 0.134/0.139/0.173/0.197

**陷波**:N = delta[n-D] - 0.9*B。因訊號能量主要在帶外,rms(N*x) 近似 rms(x),
所以 rb/(rb+rn) 近似「帶內能量佔總能量的比例」。需要 ROM 多一組 33-tap 係數。

**fast/g3 更省**:G(sigma3) 是寬頻低通、近似總能量,而且**已經在 18 維輸出裡**。
這個判別量不需要新濾波器、不動 ROM、不動 RTL,只是兩個現有輸出相除。

**尚未確立**:n=4。今天已多次看到指標隨批次翻轉,必須用第二場(每類 3 次)當
**獨立驗證集**重現,才能寫進論文。若重現,C 對 G 的能力型主張成立:
「振幅相同、時間結構不同,前端輸出差 3.8 倍」。

全頻段(電感掃頻 2.1-35.5 Hz)上四者差異不大(r 皆 > 0.99),所以這個修正
專門解決的是**寬頻邊緣刺激**的情況,不是頻率響應本身。


## 9. 等振幅掃頻:編碼的頻率解析能力(2026-08-27)

**這是唯一站得住的能力型結果。** 輸入是合成的等振幅對數掃頻(0.5->120 Hz,240 s),
雜訊用實測頻譜(sd 27.94),三個判別量全部報告,完全不涉及操作者或感測器。

    Hz      fast/slow    fast/g3    f/(f+notch)
     1        0.070       0.038        0.033
     5        0.187       0.742        0.148
    20        1.129      10.128        0.467
    35        3.579      20.276        0.557
    60        6.324      28.007        0.444
   100        3.946      16.815        0.177   <- 已翻轉

**單調性(Spearman,可用範圍 1-60 Hz)**

    fast/slow    +0.9996
    fast/g3      +1.0000   <- 完美單調
    slow/g3      +0.7522

(先前報的 0.97-0.98 是 log-log Pearson 且含 60 Hz 以上已翻轉的區段,兩者都選錯。)

**組合是相加的** —— 用判別量反推頻率的幾何標準誤:

    slow/g3 單獨            93.7%
    fast/slow 單獨          26.5%
    fast/g3 單獨            13.7%
    fast/slow + fast/g3      6.9%
    三個全用                 3.2%   <- 最佳單一比值的 1/4

三者高度相關(fast/slow vs fast/g3 r=0.96)但**不冗餘**。這回答了「為何要三個尺度
而不是兩個」,而且是量化的。

**振幅不變性**:振幅跨 16 倍(500->8000 counts)時,同一頻率的判別量變異 0.2-8.7%。

**可寫的主張**:振幅固定時三尺度輸出可將刺激頻率估計到 3.2%(1-60 Hz);任何單一
比值最好 13.7%;只回報單一振幅的前端無法估計。

**界限**:這刻畫的是**編碼**,不是端到端硬體。真實感測器的非線性會壓縮它(FSR 上
已量到)。可用範圍 1-60 Hz,超過會翻轉。

## 10. 係數位寬是目前的雜訊瓶頸(2026-08-27)

係數量化 SNR(隨機訊號實測,對照無量化的浮點核):

    格式        DoG_fast   DoG_slow   G(sigma3)
    Q15(現行)     73.6      62.2       55.4    <- G(s3) 比類比低 7 dB
    Q16            78.2      67.6       60.9
    Q17            84.7      74.3       67.3
    Q18            90.2      79.8       73.0

    類比雜訊底 = 24.9 counts / 32767 = 62.4 dB

**G(sigma3) 通道目前受算術限制,不是受感測器限制。** sigma3=85 很寬,係數攤在
256 taps 上、數值小,Q15 的相對量化損失最大。

而 G(sigma3) 正是第 9 節最佳判別量 fast/g3 的**分母**。

合成效果:Q15 -> 54.6 dB,Q17 -> 61.2 dB,**改善 6.6 dB(雜訊減半)**。
代價只有係數 ROM 768x16 -> 768x18;Gowin DSP 原生 18x18,乘法器很可能免費。

**資源餘裕**(2026-08-26 board build):Logic 3550/8640(2.43x 餘裕)、
Register 2154/6693、BSRAM 5/26、DSP 4/10。fast/g3 判別量在下游計算,前端 0 LUT。

**框架修正**:「低邏輯閘」是關於**矽化**的主張,不是 FPGA 原型的。原型剩餘容量應
用於驗證與監控(係數精度、即時故障偵測)。今天三個失效模式(SPI 相位、FFC 間歇、
順應層市電注入)全部只在離線分析才發現;FFC 間歇會產生相鄰樣本差 270 counts,
硬體上一個比較器就能即時抓到。

`ttcgs_board` 在此之前**從未燒錄過** —— 論文中的特徵是由 `top_dual` 的 ASCII UART

### 結果:特徵路徑正確

    靜止        d0 = 1±12.8   d1 = 0±11.2   d2 = 1780±4.6    mask 0%
    10s 按下    d0 尖峰 7743                                  mask 開始
    11-17s 持續 d2 = 32767    d0 = 0(無變化,快分支正確歸零)  mask bit2 100%

### 四個只有硬體會暴露的問題

**(a) 反向通道無逾時 —— 設計缺陷**
`halfduplex_ctrl` 的 D_RX 等反向幀,而 `pack_start` 要求 `dir_state == D_TX`。
對端沉默(或未連接)時狀態機永久卡在 D_RX,**前端停止產生特徵且無任何指示**。
模擬測不到,因為測試台一定會回覆。已加 2.4 ms 看門狗。

**(b) 取樣不等轉換器就緒 —— 設計缺陷**
`start_sweep` 自 reset 起以 1 kHz 開跑,但 ADS 需 POR+GAP+設定寫入(~15 ms),
DoG 的 256-tap 緩衝需 256 ms。校正窗(CAL_N=512)因此落在啟動暫態上,暫態近似
緩變使 N*sumsq ~ (sum)^2,算出的變異數趨近零 → **全部 18 維標死**、門檻退回地板、
mask 在 90% 的幀觸發。實測 dead = 0x3FFFF 而 DoG 輸出 sd 明明有 1200-4900。
已改為等 `ads_init_done`(鎖存)+ 20 ms。**注意不可等 LDC**:LDC 驅動在讀不到
CHIP_ID 時反覆重跑初始化,`ldc_init_done` 永不穩定,拿它當閘控會讓取樣永不開始。

**(c) G(sigma3) 係數總和溢位 —— 正確性 bug**

    DoG_fast   sum = 32768  (1.000000)
    DoG_slow   sum = 32767  (0.999969)
    G(sigma3)  sum = 32775  (1.000214)   <- 多 7 LSB

sigma3=85 攤在 256 taps、每項最大僅 307,Q15 捨入誤差累積。滿刻度輸入
32767 * 32775/32768 = 32773 > 32767,而輸出級**截斷而非飽和** → 回繞成 -32763。
硬體實測:持續按壓時 d2 = **-32763** 且 mask 持續觸發,**下游看到的抓握位準反轉**。
已在 `gen_coeffs.py` 加入總和精確歸一(殘差分攤到最大係數上),三核皆為 32768,
修正後實測 d2 最小 1765、負值 0 幀。

**bit-exact 黃金模型驗證沒抓到它** —— 測試向量顯然未涵蓋滿刻度輸入。這是驗證
覆蓋率的缺口,重新產生向量時應加入滿刻度案例。

**(d) 鏡射單緩衝競爭**(本次新寫的工具,非既有設計)
packer 在串流期間持續寫入同一緩衝,造成 17.6% 的幀 CRC 失敗。改雙緩衝後為 0%。
