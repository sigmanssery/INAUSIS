# 偵測規格(2026-08-28 / 29)

真值來源分兩種:**合成刺激**(時序解析度,由建構決定)與
**真實接觸配上原始通道 dim12 當刺激真值**(偵測延遲)。兩者都不依賴操作者的一致性。

主張從「分辨手勢」收窄成「**告訴下游有沒有接觸、在哪一維**」之後量的規格。
這正是 TTCGS 本來的輸出:給下游 SoC 的注意力遮罩(`mask` / `mask_failsafe` /
`dead`),分類是後來才加上去、而且兩次複現都失敗的東西。

真值由 `synth_press` 建構決定,**不依賴任何人的手**。

## 靜止誤判率

**只用確定沒接觸的錄音**(手離開 30 cm / 懸空 2 cm / 手指靜放不施力 /
冷開機檢查),合計 **80,424 幀 = 116.7 秒**:

    接觸旗標 (status bit2)   0 幀
    mask dim0 (DoG_fast)     0 幀
    mask dim1 (DoG_slow)     0 幀
    mask dim2 (G_s3)         0 幀

**三個活維度全部零誤觸發**,包括手指靜放在感測器上的 30 秒。

> **更正**:本節原記 dim0 誤觸發 0.606%。那個數字是拿語料庫檔案的「前 3 秒」
> 當靜止算的,而那些窗並非靜止(`H3_slide2` 一開始就在滑,d0 變異 423,240)。
> **同一個錯誤犯了兩次**(另一次是挑 `VAR_CEIL` 的基準值)——
> **靜止基準只能用確定沒碰過的錄音。**

對照:真實按壓時 dim0 的觸發持續中位 28 幀 = 40 ms(n=26,全距 1~59)。

## 偵測延遲:用真實接觸重測(2026-08-29)

合成刺激那條路被白雜訊擋住(見下),但**原始通道 dim12 本身就是精確的刺激真值** ——
它是未濾波的轉換器輸出。以「raw 跨過自身峰值 10%」為起點、
「mask 任一活維度拉起」為終點,量既有的真實按壓/滑動錄音:

    115 個事件(`2026-08-28_H2_*` 與 `H3_*`)
    延遲中位 **2 個樣本 = 2.90 ms**,全距 0~6 樣本
    與事件峰值無關(22000~30000 與 30000+ 兩箱皆為 2 樣本)

### 5σ 重測:延遲不變(2026-08-29 定案)

以現行 5σ 組態重錄:

    firm 按壓 8 次   延遲 **全部 2 樣本**,零離散
    分級按壓 16 次   中位 2 樣本,16 個裡 14 個落在 2~3 樣本
    合計 24 個事件於 5σ;對照 3σ 的 115 個事件,中位同為 2 樣本 = 2.90 ms

**門檻提高 2.78 倍完全沒有增加延遲。** 按壓的上升緣夠陡,DoG_fast 在同一個
樣本內衝過兩個門檻,所以延遲由**核的前載形狀**決定而非由門檻決定。

### 為什麼偵測下限用手指探不到

要求操作者做「由弱到強」的階梯後發現:

    raw(未濾波瞬時值) 峰值 24857 ~ 30986   <- 幾乎不隨力道變化
    d2(低通後持續載荷)峰值  4828 ~ 19929   <- 六倍跨度

**手指再輕,接觸的上升緣仍然很陡**,raw 照樣接近滿刻度;變輕的是持續載荷。
而偵測由快頻帶觸發,所以每一次都輕鬆越過門檻 —— 16 次全部偵測到,零漏。

**要接近偵測下限,需要「振幅小 *且* 上升緩慢」的刺激,那是手做不出來的。**
這正是合成產生器的用途,而那條路目前卡在白雜訊(見下)。
**下限因此仍然未知,原因是刺激源而不是設備。**

### 為什麼 2.90 ms 在機制上說得通

濾波器核是**因果且前載**的,不是置中的對稱高斯:

    G_s1      能量重心 tap  5.3 =  7.7 ms   峰值在 tap 5
    G_s2      能量重心 tap  9.1 = 13.1 ms
    DoG_fast  能量重心 tap  9.2 = 13.4 ms   50% 能量在 tap 7 = 10.2 ms
    G_s3      能量重心 tap 67.0 = 97.2 ms   <- 只有它是長的

tap 0 就有權重,所以陡峭上升緣一進來輸出立刻開始動。
若核是置中對稱的,群延遲會是 128 樣本 = 186 ms,那與觀測不符。

# 合成雜訊的根因與修法(2026-08-29,已解)

## 症狀

合成刺激下 `G_s3` 的靜止變異只有 **0.1**,真實感測器是 **4.65**。門檻因此低到
`dim2` 幾乎持續觸發,第一次偵測下限掃描整個作廢。

## 走錯的路(丟掉一整晚)

假設真實雜訊是 1/f,想用漏積分器「補低頻」。**假設本身是錯的。**

拿 10 小時 soak 的第 2 小時、5 分鐘窗量真實靜止頻譜:

    0.1~1 Hz  1~5 Hz  5~20 Hz  20~60 Hz   相對 1~5 Hz
     -0.0 dB  +0.0 dB  +0.2 dB   +1.2 dB
    細看 G_s3 通帶內:0.1~0.3 / 0.3~0.6 / 0.6~1.0 / 1.0~1.8 Hz
                      +0.4    +0.1     -0.4     +0.0 dB

**真實雜訊在 0.1~30 Hz 平坦到 ±0.4 dB —— 是白的,沒有 1/f。**
抬高的只有 60~200 Hz 的市電諧波。異常的是合成端,不是真實端。

## 真正的根因:LFSR 每個樣本只移一位

`lfsr[6:0]` 取 7 個位元,而每個樣本只右移一位 ——
**相鄰兩個樣本共用其中 6 個位元**,序列因此強相關,不是白雜訊。

Python 用真實量化係數驗證(每個樣本推進的步數):

    步數/樣本   raw 變異   d2 變異   d2/raw     相鄰自相關
        1        1365.2     0.151   0.00011      -0.247
        2        1370.5     5.960   0.00435      -0.130
        8        1366.1     9.092   0.00666      -0.002
    真實感測器    1085.0     4.650   0.00429

**每樣本推進 8 步**(8 個位元不重疊)就恢復成白雜訊。
八步線性遞迴仍是線性的,所以合成成一個固定 XOR 網路,不佔時脈。

與真實值 0.00429 的殘差**不是缺陷**:真實訊號有 30~40% 的功率在 60 Hz 以上的
市電諧波,那些被 `G_s3` 擋掉,所以真實比值低於純白雜訊。合成端不該複製市電,
**0.0066 就是正確的目標**。

## 硬體驗證

修法後同一顆合成 bitstream:`dim2` 在 12 個零載荷週期**全部 0% 觸發**,
只在產生器刻意施加載荷的 4 個週期觸發 100%,而量到的抬升
(+48 / +90 / +170 / +327)精確追蹤設定值(40 / 80 / 160 / 320)。

> 先前記的「dim2 free-run 31~57%」歸因有誤 ——
> 那批數字混了校正窗污染與這個**合法**的載荷觸發。

## 方法論

昨晚在 RTL 上連續猜錯四次;今天先在 Python 用真實係數把假設驗完才動 RTL,
一次就對。**先量目標(10 小時 soak 給了真實頻譜),再設計。**
