## 根因:一次性校正的估計器誤差(v6 的問題)

`CAL_N=512` 對 d2(G_s3,自相關時間 **τ=84 幀**)只有 **~6 個獨立樣本**。
χ² 六自由度 → σ 估計 0.52×~1.45× → **標稱 5σ 實際落在 2.6σ~7.3σ**。

實測六次開機:**低於 0.007% ~ 0.083%**,與模型吻合。
d0 的 τ=3(170 個有效樣本)所以從沒出事 —— **壞的一定是慢維度**。

**分佈本身是高斯的**(kurtosis 2.9);以錄製自身的 sd 算,5σ 超越率是 **0**。
**錯的是估計器不是模型。**

## v8:每樣本 EWMA —— 修好靜止,**賠掉下限**

```verilog
threshold <- threshold + (N_SQ*cmp_sq - threshold) >> ROLL_K
```

靜止十分鐘 0 / 413,516、五輪開機全距 0.0000、按壓 19/19。
**但合成下限掃描:55 counts 從 100% 掉到 67%,中段延遲成 1.5 倍。**

### 為什麼

守衛區**只在觸發時武裝**。所以**次閾值刺激完全沒有守衛** —— 它的能量直接進入
雜訊估計、把門檻推高,**於是把自己推得更低於門檻**。正回饋。

- 靜止測試看不到(沒有訊號)
- 按壓測試看不到(按壓大到每次都觸發,守衛每次都武裝)
- **只有在下限附近才會咬**

雷達裡叫 **target masking**,是 CA-CFAR 的已知失效模式。

### 順帶:v7 的定點災難

第一版寫成 `thr + ((tgt - thr) >>> 12)`。門檻只有 ~118,`>>>12` 讓
**正差變 0、負差變 −1**(算術右移向 −∞)→ **0.17 秒歸零,88~99% 的幀觸發**。
修法是累加器加寬當小數。**選移位量前先看被移位的數有多大。**

## v9:整窗取捨 —— 修好下限,**開機暫態**

不再連續混合,改成**重複跑 CAL_N 窗,整窗接受或拒收**:

```
每窗結束:  new_var = Σcmp²/512
           若 new_var <= 4 × ref_var  ->  收,併入平均(AVG_K=3,約 8 窗)
           否則                       ->  整窗丟棄
           連續拒收 8 次              ->  強制接受(環境真的變了的逃生口)
```

**關鍵在「能不能拒絕」。** EWMA 每個樣本都必須摻進去,窗式可以整個丟掉,
所以次閾值刺激再也推不動門檻。

**拒收判準必須是相對的**:一個 55 counts 的按壓在 512 樣本窗裡只貢獻約
700~1400 counts²,**遠低於 `VAR_CEIL=20000`**,但那是靜止 4.7 的 **300 倍**。
絕對門檻抓不到,相對比值抓得到。

**成本上也贏**:窗累加的是 `cmp_sq`(比較本來就在算),`μ` 在第一次校準後已知,
所以 sum / sum² 都不需要 —— **DSP 從 70% 回到 50%**。

### 但 1/5 輪開機有 42 次觸發

全部落在 **t=0.49~0.57 秒的 80 毫秒內**,之後 59.4 秒完全乾淨,d2 的 sd
全程不變(1.88~2.37)。**是收斂暫態,不是穩態失效** —— 種子(一次性估計)
偏低,窗平均隨即修正。

對照 v6 的 343 次是**散在整整十分鐘**,性質完全不同。

## v10:保守種子 + 收斂旗標 —— 暫態消失

**兩處改動:**

1. **種子取 2σ² 而非 σ²。** 種子誤差是對稱的,但後果不是:**偏低會誤觸發,
   偏高只是短暫遲鈍而且會被窗平均消掉**。偏向失效安全的一側。
2. **`uncal` 撐到收斂。** 累積 `CONV_N=8` 個被接受的窗之前保持 1。

### 結果

```
五輪開機:總觸發 0 / 0 / 0 / 0 / 0    uncal 清除於 4.02 / 4.00 / 4.07 / 4.02 / 4.09 s
合成下限:八階全部 100%,延遲與 v9 逐階相同(保守種子零代價)
十分鐘靜止:0 / 413,515
```

保守種子還有一個沒預期到的效果:**收斂變單調**(門檻只從高處往下走),
所以連暫態的觸發都沒有 —— 42 次那個爆發直接消失,不是被標記掉而已。

### `uncal` 的語意升級(要改論文 §III-E)

原本是「一次性校正還沒做完」,**暗含「校正做完就可信」這個錯的假設**。
現在是「**這一維的雜訊估計還沒收斂到可以信任**」。

**⚠ 時間基準的注意事項**:五輪開機測得 4.00~4.09 s(全距 0.09 s)是
**同一套程序重複五次**的可重現值;十分鐘那次量到 6.74 s,因為錄製起點相對於
上電的對齊不同。**要寫進論文的「自上電起算」絕對時間需要另外量。**

## 通則(不只適用本專案)

1. **雜訊估計不能只做一次** —— 一次窗的估計器誤差可能比訊號還大。
2. **不能連續混合** —— 連續平均無法拒絕,次閾值訊號會自我遮蔽。
   能拒絕的估計器(整窗取捨、秩統計)才對。
3. **拒收判準要相對,不要絕對** —— 絕對上界必然либо太鬆либо太緊。
4. **估計器要誠實說出自己何時可信** —— 否則下游會信一個還沒收斂的門檻。
5. **零誤觸發可以靠把門檻拉高白拿** —— 靜止與下限**必須一起量**,
   今晚 v8 就是只量一邊而看起來成功的。

## 還沒做

- **窗累加器寬度保守過頭**:每維兩個 44 位元(為「整窗都是滿刻度」的最壞情況),
  而那種窗本來就會被拒收。改飽和加法應可砍掉 Logic 的大部分增量(+1152 對 v6)。
- **秩統計版本**:中位數對污染不敏感,連守衛區都可省。先讀 **CADENAS 2015**
  (管線化中位數、整數位元切片、FPGA 面積省 40%、**不吃乘法器**)。
- **`uncal` 自上電起算的絕對收斂時間**需要獨立量測。

# 偵測下限:「沒有硬性下限」已被推翻(2026-08-30 深夜)

先前寫「沒有硬下限,55 counts 仍 100% 偵測」。**那是產生器的限制,不是鏈的性質** ——
`synth_press` 的增量最小只能到 1 count/樣本,乘上 55 個上升樣本就是 55,掃不到更低。

`level` 加 4 個小數位讓增量可小於 1 之後(上升時間固定 55 樣本,只降振幅,
所以振幅與起始形狀不混淆),下限立刻出現:

| 峰值 (counts) | 偵測 | 對 d2 雜訊 |
|---:|---:|---:|
| 55 | 5/5 **100%** | 17σ |
| 41 | 5/5 **100%** | 13σ |
| **27** | **3/5 60%** | **8.5σ** |
| 20 | 0/5 **0%** | 6.3σ |
| 13 及以下 | 0/5 0% | — |

**下限在 20~41 counts 之間,50% 點約 27。**

## 為什麼比簡單的 5σ 預測高 1.7 倍

乾淨間隙(16,000 樣本)量到 raw sd **36.78**(對上 LFSR 的 ±64 均勻分佈)、
d2 sd **3.158**。簡單預測 5σ × 3.158 = **15.8 counts**,實測 50% 在 **27**。

**最可能是保守種子。** v10 的種子是 **2σ²**,而這個掃描每 1.5 秒一次按壓 ——
窗經常被污染而拒收,參考值**停在種子上沒收斂下來**。等效門檻因此是
25 × 2σ² → **7.07σ**,預測 **22.3 counts**,與實測吻合得多。

**這是正確行為不是誤差**(估計器拒絕從污染資料學習),但必須寫進規格:
**在重複刺激下,下限比靜止時差 √2 倍。**

## 換算到真實感測器(外推,非量測)

    合成 d2 sd 3.158   真實 d2 sd 2.212(十分鐘靜止)  -> 合成吵 1.43 倍
    真實鏈下限估計     27 / 1.43 = 約 19 counts

**這是外推。** 兩邊雜訊譜形狀不同(合成白、真實帶市電),而且合成**完全繞過 ADS**。
端到端下限要等 AD5254 到貨,把同一組階梯穿過真實類比路徑再跑一次。

## 論文 §IV-D 要改

「no hard detection floor」換成上表那條曲線,並附兩句限制:
**(a)** 合成雜訊比真實吵 1.43 倍;**(b)** 重複刺激下等效門檻是 7.07σ 而非 5σ,
所以這是**保守**的下限。

**這比原來的主張強** —— 一條有轉折區、可證偽、可與理論對照的曲線,
勝過「我們找不到下限」。

# ⚠ v10 的守衛鎖死(2026-09-01 由一週連續運行的 soak 揭露)

**受控測試全數通過的 v10,在長時間真實運行下會把自己的門檻鎖死。**

## 現象

板子連續運行約一週(未斷電、未移動),錄 10 小時(00:00 起,幀率 689.0,
時戳不連續 1 —— 擷取乾淨):

| 時鐘 | dim1 觸發 | dim1 靜止 sd | **觸發時 / sd** | 守衛佔空 |
|---|---:|---:|---:|---:|
| 00:00 | 150,605 | 13.48 | **3.1** | 100% |
| 01:00 | 39,318 | 10.54 | **3.1** | 100% |
| 03:00 | 31,427 | 10.13 | **3.2** | 100% |
| 05:00 | 2,428 | 8.80 | 3.6 | 13% |
| 06:00 | **0** | 8.57 | — | — |
| 08:00 | 0 | 17.54 | — | — |

**dim1 在 3.1~3.6σ 觸發,而規格是 5σ。** 同一時間 **dim0 在 5.1σ 觸發(正確)** ——
它整晚沒觸發過,所以從沒進入鎖死。

## 機制

```verilog
wire s2_roll = ROLL_EN && s2_run && !s2_guarded;   // 守衛時不累加
if (over_thr) guard_cnt[s2_dim] <= GUARD_N;        // 每次觸發重新武裝
```

`GUARD_N = 128` 幀。dim1 的觸發間隔中位是 **40 幀**,**78~97% 的間隔小於 128** ——
守衛連續武裝,**窗累加器五小時沒有前進過**,門檻凍結在偏低值,於是繼續觸發。

**自我維持,而且沒有出口**:`REJ_MAX` 只救「完成但被拒收」的窗,
**不救「根本沒完成」的窗**。設計時沒想到會有這個狀態。

## 為什麼受控測試抓不到

十分鐘靜止、五輪開機、按壓 19/19、合成下限掃描 —— **四個全過,四個都太短**。
鎖死需要先有一段**密集**觸發(> 1 次 / 128 幀),而受控測試裡從來沒出現過。

**這個 bug 是由「一週連續運行 + 十小時錄製」揭露的,不是由任何設計中的測試。**

## 修法(v11)

守衛佔空看門狗:某維連續被守衛 `GSTALL_MAX = 2048` 個樣本週期(4×CAL_N,
約 3 秒)後,**強制累加一次**。窗因此得以完成,回到既有的相對接受/拒收路徑,
`REJ_MAX` 成為第二級出口。最壞情況從「永久卡死」變成「有界的卡住」。

資源:Logic 5568 → 5778(+210)、Register 3117 → 3357(+240)、**DSP 維持 50%**。

## 尚未驗證

**我無法用合成刺激快速重現鎖死條件** —— `synth_press` 現行程式每 1.5 秒一次按壓,
守衛佔空只有約 12%,不會鎖。要重現得改 PERIOD/rise/hold,那是另一份工作。

**真正的驗證是再跑一次過夜 soak**(揭露它的就是這個)。判準:
dim1 的「觸發時 / 該小時靜止 sd」應該回到 **5.0 附近**,而不是 3.1~3.6。

## 兩個一併修正的解讀錯誤

錄製時間是關鍵:**08-30 那份是早上 09:10 起(白天),09-01 是午夜 00:00 起**。

- ❌「觸發是真實環境擾動」—— 錯。凌晨 01:00~05:00 最安靜卻觸發最多。
- ❌「自適應門檻在安靜時變敏感,所以觸發變多」—— 錯。那會落在 5σ,實測 3.2σ。
- ✅ **門檻被守衛鎖死在偏低值。**

另外 **08-30 那份幀率只有 622.7/s、時戳不連續 99 次**(主機端掉幀約 10%),
**不可用來報數字**。

那條記錄讓我們把工具唯一的完整性檢查當成雜訊忽略了。**燒錄是會真的壞的。**

**可用的替代檢查:User Code 對同一個 bitstream 是確定的。**

**規則:每個 `.fs` 第一次燒錄時記下 User Code,之後每次比對;不一致就是寫壞了,

# 守衛鎖死:復現、A/B、修好(v12,2026-09-02)

## 復現方式(可重跑)

`synth_press` 加 `SUSTAIN` 模式:安靜前導後**永久維持 +300 counts 直流偏移**。
ABS 觸發的 G_s3(dim2)因此每個樣本都超過門檻,守衛連續武裝 —— **正是鎖死條件**。

    ttcgs_board.v:  synth_press #(.SUSTAIN(1'b1)) u_synth (...)   SYNTH=1

**⚠ 觀測點要接對維度。** 第一次我把儀器接在 dim1 上,而觸發的是 dim2
(常數的變化率是零,ROC 維度不會響應),結果 A/B 顯示「沒有差別」,
差點得到相反結論。**接 `DBG_LIVE = 2`。**

## 三方 A/B(持續偏移,60 秒,看 dim2 自己的 win_cnt)

| | win_cnt 相異值 | acc_cnt 末值 | 觸發率 |
|---|---:|---:|---:|
| **v10** 無看門狗 | **1 / 512**(58 秒卡在 381) | 0 | 100.0% |
| **v11** 每 GSTALL_MAX 放行一個樣本 | 18 / 512 | 0 | 100.0% |
| **v12** latch 到窗完成 | **512 / 512** | **8** | **48.4%** |

**v11 在紙上正確,實務上慢了 2000 倍** —— 每 3 秒一個樣本,填滿 512 樣本的窗要
25 分鐘,收斂要 3.4 小時。**「邏輯上會脫困」不等於「實務上脫得了困」。**

## v12 的修法

```verilog
if (w_full)          gstall_cnt <= 0;              // 窗完成才重新武裝
else if (s2_force)   gstall_cnt <= s2_gst;         // 已觸發 -> 保持,latch
else if (s2_guarded) gstall_cnt <= s2_gst + 1;
else                 gstall_cnt <= 0;
```

一旦看門狗觸發就**保持到窗完成**,窗因此在 0.74 秒內填滿,回到相對接受/拒收,
`REJ_MAX` 當第二級出口。

## ⚠ 順帶暴露一條要寫進論文的行為規格

v12 的觸發率從 100% 掉到 48.4%,是因為 **`REJ_MAX` 把持續負載當成新基線接受了**。
那是設計本意(環境真的變了就該採納),但意味著:

> **持續狀態只會被回報約 45 秒,之後被吸收成新基線。**

**這跟 §III-E「G_s3 的絕對值觸發保留握持狀態資訊」的主張有張力** ——
握著一個東西超過一分鐘,它就不再被回報。必須寫清楚,不能留給讀者假設。
