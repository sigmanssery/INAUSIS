# 一、成立(已驗證)

## 1. v6:常數乘法強度削減,DSP 7.5 → 5

`zscore_flag_multi.v` 的 `($signed(N_SQ) * cal_var16) >>> 4` 改成依 `N_SQ` 設位元
展開的移位加法樹。`N_SQ` 是 `parameter`(=25),**寫成 `*` 讓合成器推導出一顆
40×5 的真乘法器**。

| | v5 | **v6** | Δ |
|---|---:|---:|---:|
| DSP | 7.5/10 (75%) | **5/10 (50%)** | −2.5 |
| — MULTADDALU18X18 | 3 | 1 | −2 |
| Logic | 4299 | 4374 | +75(全是 ALU,LUT 一個沒動) |
| Fmax | 40.477 | 37.301 MHz | −3.2(對 27 MHz 仍 38% 餘裕) |
| 功耗 | 37.011 | 37.051 mW | +0.040 |

**行為位元相同**:40 位元語意下 300,012 個值(邊界 + 全域隨機)零不符。
所以 v5 上量到的 soak / 5σ / 延遲數據對 v6 有效。

**`DSP 7.5` 已作廢。** 之前以為那是 5σ 的代價,錯了 —— 5σ 本身幾乎不花東西。

# 三、失敗(記下來避免重犯)

## v7 滾動基線第一版:定點移位的不對稱捨入

```verilog
thr_roll = s2_thr + ((roll_tgt - s2_thr) >>> 12);   // 錯
```

門檻約 **118**,`>>> 12` 是除以 4096:**正差變 0、負差變 −1**
(算術右移向 −∞ 取整)。門檻每樣本至少掉 1,**0.17 秒歸零**,
之後 **88~99% 的幀觸發**(五輪實測)。

**修法**:累加器加寬 ROLL_K 位當小數,被移位的是 `roll_acc`(約 4.8e5)
而非三位數的差值;向下取整讓估計略偏高,失效方向安全。

**教訓**:算對設計意圖不等於算對算術。**選移位量前先看被移位的數有多大。**
(與「把編譯期常數寫成 `*`」同類,同一天犯兩次。)
